# Turn this recorded procedure into a reusable Agent Skill

You are in a skill folder generated by stepcap from one or more screen recordings of a person doing
a task (SKILL.md says how many). The screenshots and `_context/` files come from the first one.

- `SKILL.md` - the draft skill. **This is the file you rewrite.**
- `references/step-NN.png` - annotated screenshots: a numbered frame or ring marks the element that
  was clicked in step NN; an arrow marks a drag or scroll. Look at them.
- `_context/steps.json` - the steps (titles and descriptions may have been edited by the person).
- `_context/events.jsonl` - the raw event log (clicks, typing, app switches, URLs, clipboard,
  terminal commands). Secrets were already replaced with `[REDACTED:kind]`.

## What to produce

Rewrite `SKILL.md` so an agent can do **this kind of task again, with different inputs**:

1. **Generalise.** One recording shows one example. Describe the procedure for the whole family of
   similar tasks (another project name, another date, another customer). Keep the example values
   only as examples.
2. **Prefer tools over clicks.** If a step can be done with a CLI, an API, a config file or a
   script, say so and describe that way first; keep the UI steps as the fallback. Do not invent
   commands or endpoints you are not sure exist - say "if available" or leave it out.
3. **Inputs are variables.** Everything the person typed or picked that would change next time is
   an input written as `{{snake_case_name}}` and listed under `## Inputs` with a one-line
   meaning. Never write a real password, token, e-mail address or customer name.
4. **Mark confirmations.** Any step that deletes, sends, publishes, pays, or changes permissions
   must say "Ask the user to confirm before ...".
5. **Keep it checkable.** Each step says what should be visible afterwards, so the agent can tell
   whether it worked. Reference screenshots with relative links like
   `[step 3](references/step-03.png)`; do not rename or delete files in `references/`.

## Format rules (the result is validated; breaking them fails the run)

- Keep the YAML frontmatter. `name` must stay exactly as it is (it must equal the folder name).
- `description`: one or two sentences, max 1024 characters: what the skill does **and when to use
  it**, with the words a user would say when asking for it.
- Sections: `## Goal`, `## Inputs`, `## Steps` (numbered), `## Checks`, `## Notes for the agent`.
- Under 500 lines and under about 5000 tokens. Be concise.
- Write in the same language as the step titles in `_context/steps.json`.
- Edit only `SKILL.md`. Do not create other files, do not run commands that change anything
  outside this folder, and do not access the network.
