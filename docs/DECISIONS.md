# Decisions

One line per decision, newest last. Format: `YYYY-MM-DD — decision — reason`.

- 2026-09-24 — Name stays `stepcap` — PyPI has no `stepcap` project (404) and no OSS tool of that name was found; the only hit is an unrelated finance company (StepCap, LLC).
- 2026-09-24 — Python 3.11+, runtime deps limited to Pillow, mss, pynput — per spec; everything else is stdlib.
- 2026-09-24 — Build backend: hatchling, src layout, version single-sourced in `pyproject.toml` + `__init__.py` (both bumped by release-please) — `importlib.metadata` is unreliable inside PyInstaller binaries.
- 2026-09-24 — `EventProcessor` is pure logic fed by both the recorder and `simulate` — debounce/drag/scroll/mask behaviour is identical in tests and real use, and testable without OS hooks.
- 2026-09-24 — Hook callbacks only enqueue; a processor thread grabs the screen, a writer thread encodes PNG — slow disks never block hooks (Windows removes slow low-level hooks) and click→grab latency is measured.
- 2026-09-24 — Screenshot is taken on mouse *press* — shows the UI state before the click changes it (what the reader must find).
- 2026-09-24 — Double-click = second press within 150 ms of the first *release* (configurable `--double-click-ms`) and within the drag threshold — spec says 150 ms; release→press is the stable part of a human double-click.
- 2026-09-24 — Drag threshold 12 logical px; scroll runs end after 0.8 s idle or on direction change.
- 2026-09-24 — Typing: default stores only char count + Enter; Tab ends a run (form fields); Enter/Esc outside typing and Ctrl/Alt/Cmd combos become `key` steps; arrows/F-keys ignored.
- 2026-09-24 — Forced mask list extends the spec (password/パスワード/1Password/Bitwarden/KeePass) with passwd, passcode, LastPass, Keychain, sign in/login/ログイン/サインイン — login pages usually contain password fields.
- 2026-09-24 — `--exclude-app` matches case-insensitive substrings of app name *or* window title — app names are not always available (best-effort lookup).
- 2026-09-24 — raw/ keeps lossless PNG (compress_level=1 for speed); the guide uses WebP q85 by default (`--image-format jpeg|png`) — spec: "PNG → WebP/JPEG on save, quality configurable".
- 2026-09-24 — Coordinates stored as absolute, monitor-relative and image-pixel (`img_x/img_y`) — handles HiDPI/Retina where image px ≠ logical px.
- 2026-09-24 — macOS window names via Quartz window list (pyobjc ships with pynput), osascript only as fallback — ~5 ms instead of ~150 ms per click and no Automation prompt; Linux falls back to python-xlib when xdotool is missing.
- 2026-09-24 — Dedupe measures changed *area* (grid of ~45 px blocks on a 320 px grayscale sample), threshold 0.98 — a per-pixel metric missed white menus opened over white UIs.
- 2026-09-24 — Dedupe compares with the first screenshot of the current run, not the previous one — avoids chaining a slow drift into one screen.
- 2026-09-24 — Reused screenshots share one `work/` file — a blur applied in `edit` covers every step that shows that screen.
- 2026-09-24 — Build output lives in the session dir (`guide.md`, `images/`, `guide.html`, `steps.json`) — matches the acceptance criteria; stale `images/step-*` files are removed, nothing else is deleted.
- 2026-09-24 — steps.json keeps `auto.title/description`; text equal to auto text is "untouched" and regenerated (e.g. `--lang`), anything else is preserved; `--reset` recreates — makes build idempotent and edit-safe.
- 2026-09-24 — HTML date comes from the session start, not "now" — rebuilding produces byte-identical files.
- 2026-09-24 — Key steps draw a key-cap pill and no ring; manual notes draw only the badge — a ring at the cursor would point at the wrong thing.
- 2026-09-24 — simulate draws with Pillow's bundled font (Pillow ≥ 10.1) — deterministic across OSes; it has no CJK glyphs, so demo screens are English.
- 2026-09-24 — New modules beyond the spec layout: `session.py` (dir I/O), `build/pipeline.py` (orchestration), `__main__.py` (python -m / PyInstaller entry).
- 2026-09-24 — GitHub Actions: checkout@v7, setup-python@v7, codeql-action@v4, upload-artifact@v7, release-please-action v5.0.0 (third-party actions SHA-pinned) — Dependabot bumps #44–#47 folded into one PR because they edit adjacent lines; each was green on its own.
- 2026-09-24 — README comparison uses prices re-checked on vendor pages (Tango Pro $22/user/mo yearly for 1–2 users; FlowShare Professional $44 yearly / $49 monthly; Scribe Pro Personal $25 yearly) instead of the spec's $24 / $45 — the spec's figures were outdated; table carries the check date and links.
- 2026-09-24 — Edit UI reorders with Pointer Events instead of HTML5 drag-and-drop — works with touch, and HTML5 DnD never fired in headless Chromium, so it could not be tested.
- 2026-09-24 — Edit server: Host-header allowlist + JSON-only POST + Origin check + CSP — local unauthenticated server must resist DNS rebinding and CSRF.
- 2026-09-24 — Blur = pixelate then Gaussian — a plain Gaussian blur of text can be partially reversed.
- 2026-09-24 — release-please bootstrapped with `release-as: 0.1.0` (manifest 0.0.0) — with bump-patch-for-minor-pre-major a `feat` would otherwise produce 0.0.1. Removed right after v0.1.0 was released.
- 2026-09-24 — Binaries are built by a reusable workflow called from release.yml — releases created with GITHUB_TOKEN do not trigger `on: release` workflows.
- 2026-09-24 — PyInstaller gets pynput backends as explicit hidden imports (`scripts/build_binary.py`) — `--collect-submodules pynput` silently drops them when no display is available at build time; doctor falls back to `__version__` when dist-info is missing in frozen apps.
- 2026-09-24 — README images use absolute raw.githubusercontent.com URLs — relative paths do not render on PyPI.
- 2026-09-24 — ROADMAP issues were created through the GitHub API (no `gh` in the build environment); `scripts/roadmap_to_issues.py` is the idempotent `gh` equivalent for later rows.
- 2026-09-24 — Frame the clicked element by flood-filling its surface colour from the click (raw/ screenshot, no new dependency) — works on every OS today; accessibility APIs (exact bounds) stay on the roadmap (RM-021).
- 2026-09-24 — Detection is conservative and falls back to the ring: reject fills that leak out of the search window, are too small/large, or are not rectangle-like (solidity < 0.88 rejects letter holes like "o"); seeds of the same colour that fall outside the first region are filled too, and any leak means "text on a page", not a control.
- 2026-09-24 — Low colour tolerance (18) — 1 px anti-aliased borders of white buttons on white bars leaked at 40.
- 2026-09-24 — `box` + `box_source` (auto/manual) live in steps.json; auto detection runs once per step, manual frames/removals from `edit` are never overwritten; `marker` (box/ring) is saved like `lang`.
- 2026-09-24 — Automatic arrow only when the frame's *longest* side is under 2.6 ring radii (checkboxes, icons) — arrows on normal buttons added noise; the badge moves to the arrow tail.
- 2026-09-24 — Auto arrows come from the side facing the image centre (at least 30° off the axes) so they stay on screen and read as "pointing at".
- 2026-09-24 — `--spotlight` is off by default (it changes the look of every image); like `marker` and `auto_arrows` it is saved in steps.json and can be toggled in `stepcap edit`.
- 2026-09-24 — Hand-drawn arrows are stored per step as `arrows: [[x1, y1, x2, y2]]` (tail → head, image px, max 10) and drawn for every step kind.
- 2026-09-24 — `checklist.html` is a third default output (`-f md,html,checklist`) — it is cheap (~40 KB for 12 steps) and on-site operators need a paper tick list more than a long guide; `-f md,html` leaves it out.
- 2026-09-24 — Checklist thumbnails are 300 px crops of a 720 px area around the target (same markers as the guide) — about 5 cm printed, readable, and 8 steps fit on an A4 page.
- 2026-09-24 — README leads with three claims: fully local, any app (browsers included), guides open in any browser. It does not claim "runs in the browser": a web page cannot observe clicks outside its own tab, so the recorder stays a local program (FAQ says so). Free-plan limits of Scribe/Tango and Steps Recorder's .mht / 25-screenshot default re-checked on vendor/Microsoft pages the same day.
- 2026-09-24 — Direction (addon spec): one recording → a guide for people **and** an Agent Skill (SKILL.md) for any agent; local, no account. Checked facts: microsoft/skill-recorder (MIT, 4.1k★) needs a GitHub account with Copilot access, sends the event timeline / screen images to GitHub's cloud when you choose Analyze, targets Microsoft Scout / Copilot Cowork / Copilot Studio, and runs on macOS, Windows 11 **and Ubuntu** (the addon's "macOS + Win11" was wrong, so "3 OSes" alone is not a differentiator against it). OpenSteps (ebanez8/openstep): MIT, Windows 10+, .NET 8/WPF, MD/HTML export. BetterStepsRecorder (Mentaleak): GPL-3.0, Windows.
- 2026-09-24 — A0: Agent Skills spec (agentskills.io/specification): `name` 1–64 chars `[a-z0-9-]`, no leading/trailing/double hyphen, **must match the parent directory**; `description` 1–1024 chars; optional `license`, `compatibility` (≤500), `metadata` (string map), `allowed-tools`; body < 5000 tokens recommended, SKILL.md < 500 lines; `references/`, `scripts/`, `assets/` subfolders. The addon's "5,000 words" became "≤ 500 lines and ≤ ~5000 tokens (estimated)".
- 2026-09-24 — A0: Claude Code loads skills from `~/.claude/skills/<name>/SKILL.md` (personal) and `.claude/skills/<name>/SKILL.md` (project); description + when_to_use are truncated at 1,536 chars in the listing (code.claude.com/docs/en/skills). Codex loads from `$CWD/.agents/skills`, parent/repo-root `.agents/skills`, `$HOME/.agents/skills`, `/etc/codex/skills` (learn.chatgpt.com/docs/build-skills); same SKILL.md format. `--install codex` uses `.agents/skills` (project = current directory) and `~/.agents/skills` (user).
- 2026-09-24 — A0: non-interactive agents. `claude -p "<prompt>"` with `--permission-mode acceptEdits` (writes inside the working directory without prompts) and `--allowedTools`; `--bare` is not used because it ignores the subscription login (needs ANTHROPIC_API_KEY). `codex exec` reads the prompt from the argument (or `-` for stdin), defaults to a read-only sandbox, `--sandbox workspace-write` allows edits, `-C DIR` sets the directory, `--skip-git-repo-check` allows non-git folders, `--image a.png,b.png` attaches images; `--full-auto` is deprecated.
- 2026-09-24 — A0: macOS browser URL (best effort, needs the Automation permission per browser, prompted by macOS on first use): Safari `URL of front document`; Chrome / Edge / Brave / Arc `URL of active tab of front window`. Windows / Linux: no URL in v0.x (roadmap).
- 2026-09-24 — Schema: the existing `format` field **is** the schema version (steps.json and session.json). The addon's `schema_version` is not added as a second field; `format` goes 1 → 2 and old files are migrated on load.
- 2026-09-24 — `stepcap skill -o OUT` writes `OUT/<name>/SKILL.md` (not `OUT/SKILL.md`) because the spec requires the folder name to equal `name`; `export --format both` therefore writes `OUT/guide/` and `OUT/skill/<name>/`.
- 2026-09-24 — URLs are opt-in (`--record-urls`), not "always": URLs carry internal hosts and tokens, typing is already opt-in, and on macOS reading them triggers an extra Automation prompt. App switches are always recorded (window names are already in every step).
- 2026-09-24 — Secret masking works on text only (events, steps.json, SKILL.md). Pixels in screenshots are not scanned; README says so and points to Blur area.
- 2026-09-24 — README headline follows the addon tagline verbatim ("... Local, no account, no Copilot."). The comparison table is replaced by the addon's columns (runs on / guide / SKILL.md / account / sends data) with rows re-checked on each project page; FlowShare, Guidde and CliqRelay rows were dropped with the old table. BetterStepsRecorder "sends data" says "none documented" because its README does not state it.
- 2026-09-24 — `stepcap check-skill DIR` added (not in the addon): the bundled meta-skill's Procedure B needs a way for an agent to validate its own edits with the same rules `stepcap skill` uses.
- 2026-09-24 — `--agent claude|codex` writes the redacted context to `SKILL_DIR/_context/` and deletes it afterwards (also on failure/cancel); the pre-agent draft is kept next to the folder as `<name>.draft.md`. Verified end-to-end with the real `claude -p` on the demo session (valid skill, generalised inputs); `codex` is covered by tests with a stand-in executable only.
- 2026-09-24 — CodeQL flagged `check-skill` / `skill` output as "clear-text logging of sensitive information" because the secret detector was named `find_secrets` (name-based heuristic). It only returns fixed category labels, never matched text (tested), so it was renamed `leak_kinds` instead of suppressing the alert.
- 2026-09-24 — session.json `format` 2: events.jsonl may contain context events (`app_switch`, `url`, `clipboard`, later `terminal`) **without `id`** and with `seq` (= the id the next step received), so step ids of existing flows do not shift. `test_session_layout` was updated to count step events only (it asserted the exact line count and format 1); no other existing assertion changed.
- 2026-09-24 — Clipboard: the first poll is the baseline (an empty/unreadable clipboard counts as ""), only changes are recorded, the preview is redacted **before** it is cut to 80 characters, and nothing is kept while an excluded app is in front; password/login windows record the length only. Verified with real hooks on Xvfb (xclip) together with `app_switch`.
- 2026-09-24 — Secret patterns with distinctive prefixes (`ghp_`, `github_pat_`, `sk-ant-`) match without a leading word boundary, so a token glued to other text is still caught; short/generic prefixes (`sk-`, `AKIA`, `eyJ`) keep the boundary to avoid false positives.
- 2026-09-24 — A3 `stepcap shell`: bash (`--rcfile` with a PROMPT_COMMAND hook) and zsh (ZDOTDIR with preexec/precmd hooks) send each finished command over an **inherited pipe** to the stepcap process, which masks secrets and appends to `SESSION_DIR/terminal.jsonl`; nothing unmasked is written to disk. `load_session` merges them by wall-clock time using `session.json` `t0_epoch`. Deviations from the addon: command output is not recorded (cannot be masked reliably; `script`/`Start-Transcript` would put raw output on disk), and Windows PowerShell is not supported yet because it cannot be tested here - it errors clearly instead. Verified with real bash 5.2 and zsh 5.9 through a pty.
- 2026-09-24 — CodeQL ignores `tests/**` (`.github/codeql/codeql-config.yml`): the redaction tests must contain fake tokens / passwords / card numbers, which CodeQL traced into `write_json` as "clear-text storage of sensitive information". `src/` is still fully analysed with security-and-quality.
- 2026-09-25 — `stepcap app` (tkinter) never records in its own process: it drives `stepcap record --control` (JSON lines on stdout, commands on stdin). On recent macOS, pynput's keyboard listener reads the keyboard layout (Carbon TSM) off the main thread, and that aborts the process once a Cocoa NSApplication (created by Tk) exists (reported in pynput issues and several downstream projects). Separate processes avoid it on every OS.
- 2026-09-25 — Consequently the F7 note prompt no longer uses tkinter inside the recorder on macOS: it uses an `osascript` dialog (separate process). In `--control` mode the note is typed into the app's bar.
- 2026-09-25 — Clicks on the recording bar are excluded by **screen rectangle** (the app sends `exclude x y w h` whenever the bar moves or resizes), not by window title: low-level hooks fire before the clicked window becomes the foreground window, so a title check would see the previous app. The bar is visible in screenshots (documented; blur it in edit).
- 2026-09-25 — The release binary opens the window when started with no arguments (double-click); `stepcap` without arguments from pip still prints help (+ a tip), so existing CLI behaviour is unchanged. tkinter is no longer excluded from the PyInstaller build.
- 2026-09-25 — Verified on Xvfb with real XTEST clicks: Start → 2 desktop clicks → Add note (typed in the bar) → OK → Stop records exactly 2 clicks + 1 note; the bar clicks are absent; Export writes `<name>-export/{guide,skill}`. Not verified on Windows/macOS hardware.
- 2026-09-25 — RM-021 element names: Windows UI Automation (`IUIAutomation::ElementFromPoint` / `GetFocusedElement`) via **comtypes** (MIT, Windows-only dependency); macOS Accessibility (`AXUIElementCopyElementAtPosition` / `AXFocusedUIElement`) via pyobjc's HIServices, already installed with pynput. Linux AT-SPI is not pip-installable, so Linux keeps window-name titles (RM-069).
- 2026-09-25 — Lookups run on one worker thread after the screenshot is taken, with a 250 ms timeout; while a lookup hangs (an app not answering) new requests return None at once. Failures never stop recording. Static text / images inside a button resolve to the button (up to 2 parents).
- 2026-09-25 — Password fields (`AXSecureTextField`, UIA `IsPassword`) never store a name, and typing that starts in one is masked even with `--record-typing` (previously only window titles triggered masking). Element names still pass through the secret redaction.
- 2026-09-25 — The element rectangle becomes the step frame (`box_source: "a11y"`) when it is at least 4 px and covers at most half of the screenshot (a whole pane is not a target); otherwise image detection runs as before. Titles use the name (`Click the "Save" button`, `ボタン「保存」をクリック`); steps without a name keep the window-name titles, so existing sessions and tests are unchanged.
- 2026-09-25 — `simulate` reports widgets as elements only with `"accessibility": true` in the spec (existing fixtures unchanged); `demos/build.py` turns it on, so README images show element titles. The Windows binary pre-generates the comtypes UI Automation wrappers at build time and bundles them (a frozen app cannot write `comtypes.gen`). CI checks the real UIA COM client on the Windows runner and the HIServices API on the macOS runner; clicking real apps on Windows/macOS is **not verified** (no hardware here).
- 2026-09-25 — `stepcap app` finished view: the agent result comes first ("For AI agents: skill (SKILL.md)" with **Add to Claude Code** / **Add to Codex** / **Create SKILL.md**, optional *generalise with the agent CLI first*), then "For people: guide" (open guide, printable checklist, edit steps). Reason: the window only offered "Export guide + skill" into a folder, which hid the point of the tool (teaching an agent a task). Add = `stepcap skill --install claude|codex --scope user` (user scope, because the window has no project directory). How to use the skill afterwards is taken from the official docs: Claude Code `/<name>`, picked up without restart unless `~/.claude/skills` did not exist when the session started (code.claude.com/docs/en/skills); Codex `$<name>` or `/skills`, restart if it does not appear (learn.chatgpt.com/docs/build-skills).
- 2026-09-25 — An installed skill is replaced only after a yes/no dialog, and only after the new skill passed validation (`run_skill` installs last); a folder without SKILL.md is never replaced. The draft folder `<session>-export/skill/<name>/` is always regenerated. The agent refine run is confirmed in a dialog (listing what the agent will read) before it starts; slow work runs on a thread and its result is applied on the Tk thread through a queue (no Tk calls from the worker).
- 2026-09-25 — Skill names: `choose_name` no longer uses the automatic default title ("Step-by-step guide" / 操作手順書), which named every untitled recording `step-by-step-guide`; it falls through to the app names. In the window, when the result is still the generic `recorded-procedure` (e.g. a Japanese title and no app name), the recording's folder name (or its time stamp) is appended, so a second recording does not replace the first skill.
- 2026-09-25 — Comparison table: added Anthropic's "Record a skill" (Claude for Mac, Cowork; Pro/Max/Team; not on Windows or Free; records screen, clicks, typing and voice; video/audio not retained, screenshots kept) from the Help Center (https://support.claude.com/en/articles/12512198-how-to-create-custom-skills). It was announced 2026-07 and was missing from the 2026-09-24 check. stepcap's differences stay factual: no plan or account, Windows/Linux too, any agent, a guide for people from the same recording, secrets masked before writing. It has no voice narration.
- 2026-09-25 — RM-046: JSON Schemas (draft 2020-12) for session.json, one events.jsonl line, steps.json and one terminal.jsonl line ship inside the package (`stepcap/schemas/`, also in the binary via `--collect-data`); `stepcap schema [name] [--path]` prints them. They document the format for other tools (MCP clients, scripts); stepcap does not validate at run time, so `jsonschema` is a dev-only dependency (MIT). `additionalProperties` is left open so newer versions can add fields; kind-specific required fields use if/then. Written from the code, then checked against simulated sessions (every event kind, accessibility, URLs, clipboard, terminal), the real EventProcessor output, editor changes (removed frame = `box: null`, arrows) and `stepcap shell` lines. `ts` may be null for a terminal command from a session without `t0_epoch` (existing behaviour, now documented).
- 2026-09-25 — Agents are data, not code: `stepcap/skill/registry.py` holds built-in agents (claude, codex, gemini, cursor, agents) and reads `agents.toml` (`$STEPCAP_AGENTS_FILE`, `%APPDATA%\stepcap\agents.toml` on Windows, else `$XDG_CONFIG_HOME` or `~/.config/stepcap/agents.toml`) to add agents or change a built-in's folders / command (TOML via the standard `tomllib`, no new dependency). A refine command must contain `{prompt}`; `{skill_dir}` and `{images}` are optional, an argument with `{images}` is dropped when there are no screenshots. Running a configured command still needs the y/N confirmation (or `--yes`). `stepcap agents [--json]` lists everything and reports config errors. Custom agents get their own button in `stepcap app`; built-ins do not get duplicates when overridden.
- 2026-09-25 — Skill folders re-checked from each tool's docs: Gemini CLI loads `~/.gemini/skills` / `.gemini/skills` and the `~/.agents/skills` / `.agents/skills` alias, `/skills reload` refreshes (geminicli.com/docs/cli/skills/); Cursor loads `.agents/skills`, `.cursor/skills`, `~/.agents/skills`, `~/.cursor/skills` and also the Claude and Codex folders, `/` invokes (cursor.com/docs/skills). So `~/.agents/skills` reaches Codex, Gemini CLI and Cursor: `--install agents` (same folder as `codex`) and the window's button is now "Add to Codex / Gemini CLI / Cursor". Gemini CLI refine = `gemini -p PROMPT --approval-mode auto_edit` (`-p` forces non-interactive mode; `auto_edit` is a documented `--approval-mode` value; `--yolo` is deprecated) from geminicli.com/docs/cli/cli-reference/; covered by tests with the command line only, not run against a real Gemini CLI. Codex images are passed as one `--image=a,b` argument (clap accepts `--flag=value`).
- 2026-09-25 — RM-067 as a coverage report, not a pass/fail gate: `skill/coverage.py` collects what the recording showed (app names, names of clicked / typed-into elements, variable inputs, URL host names, terminal commands, F7 notes) and checks that SKILL.md (description + body) still mentions each, after NFKC + case folding; element labels ignore decoration ("+ New project" = "new project"), commands match in full or by their first two words, notes match when >= 60 % of their character pairs appear (works for Japanese without a tokenizer). A good rewrite may legitimately drop items (a CLI call instead of clicks), so it is reported, not enforced: shown after `--agent` runs and in the window; `check-skill --session` fails only with `--min-coverage`. On the committed real Claude rewrite it reports 8/9 (the example card "Book venue" was generalised), the deterministic draft is always 100 %. A "dry run" of the skill against a live app is not attempted (it would mean driving the user's apps).
- 2026-09-25 — RM-066 voice notes. Microphone via sounddevice (MIT; PortAudio), speech-to-text via faster-whisper (MIT; ctranslate2 MIT, onnxruntime MIT, tokenizers / huggingface-hub Apache-2.0, PyAV BSD with LGPL FFmpeg libraries) — no AGPL. Optional extra `stepcap[voice]`; `--voice` is off by default. Audio is 16 kHz mono PCM written by a writer thread (never in the audio callback); while paused, silence replaces the microphone so nothing said during a pause is kept and the timeline stays aligned. On stop the recorder transcribes on the CPU (`int8`, VAD on), writes `voice.jsonl` (secrets masked, same timeline as events.jsonl, merged by `load_session` as `voice` context events placed before the next step, like terminal commands) and deletes `audio.wav` unless `--keep-audio`; on failure the audio is kept and `stepcap transcribe SESSION` retries later. The model (default `base`, ~150 MB; `small` recommended for Japanese) is downloaded once from Hugging Face — the only network access, documented; the audio is never uploaded. Narration is appended to each step's automatic description (edits are still kept) and becomes "Narration: ..." lines in the skill; speech before the first step becomes the Goal when there are no F7 notes. Coverage (RM-067) ignores narration (a rewrite should keep its intent, not its words).
- 2026-09-25 — Voice in the binaries: a PyInstaller onefile with faster-whisper is 137 MB instead of 38 MB (Linux) and starts in ~2.5 s every time instead of ~0.8 s warm, and `stepcap app` starts the binary twice (window + recorder). So the voice libraries ship as separate `stepcap-voice-*` editions (three more build jobs; smoke test transcribes `tests/fixtures/jfk.wav` with the tiny model) and the normal binaries stay lean; the window greys out the voice option and names the voice edition when the libraries are missing. Verified here: the voice binary transcribes the sample; `record --voice` end to end through a PulseAudio null sink as the microphone (paplay into it while clicking on Xvfb) produced the correct text in voice.jsonl and deleted audio.wav. Not verified: real microphones on Windows / macOS (permission prompts), which CI runners do not have.
- 2026-09-25 — RM-064 Windows browser URLs: UI Automation on the foreground window of chrome / msedge / firefox / brave / vivaldi / opera (by process name) — `FindFirst` of the first Edit control in tree order (the toolbar comes before the page, so the search stops at the address bar without walking the web content), then its ValuePattern value. The element is cached per window and re-found when it goes away. What the bar shows is normalised: Chrome / Edge hide `https://` so a bare host gets it back; text with spaces (a search being typed) or without a dot is ignored. UIA clients are now per thread (COM apartments) and use IUIAutomation2 Connection/TransactionTimeout = 500 ms so a hung browser cannot stall the context thread. CI opens real Chrome, Edge and Firefox on the Windows runner with a local file and checks the URL. Linux stays unsupported (RM-070, needs AT-SPI).
- 2026-09-25 — RM-044 `stepcap mcp` uses the official MCP Python SDK (`mcp` 2.2, MIT) as an optional extra instead of a hand-written JSON-RPC loop: the protocol changed to per-request versioning with `server/discover` in revision 2026-07-28 (modelcontextprotocol.io/specification/versioning) and older clients still use the `initialize` handshake; the SDK handles both. Not bundled in the binaries (its web-server dependencies are large; agents that use MCP are installed with pip / uvx anyway). Tools: list_sessions, get_steps, step_image (annotated PNG, same rendering as the guide), build_guide, make_skill (+ install, never replaces without replace=true), check_skill (+ coverage). No recording tool — an agent must not start capturing the screen and keyboard. Paths are confined to `--root` folders (default ~/Documents/stepcap and the current directory; relative paths are relative to the first root); only user-scope installs write outside them, by design. - 2026-09-25 — `stepcap share` (RM-071): the page is encrypted, not obfuscated. AES-256-GCM with a random 12-byte nonce and a key from PBKDF2-HMAC-SHA256 (600,000 iterations, the OWASP 2023 figure; random 16-byte salt), done with `cryptography` (Apache-2.0 / BSD, now a runtime dependency) — no hand-written crypto. The browser decrypts with the standard WebCrypto API (works on file:// in Chromium; verified with Playwright: wrong password shows an error, the right one renders the guide). The password is read from a prompt (twice), `--password-stdin` or `$STEPCAP_PASSWORD`, never from argv (visible in process lists); minimum 8 characters. No expiry option on purpose: a standalone file cannot enforce it, and a fake one would mislead.
- 2026-09-25 — RM-020 OCR names, on by default at build time (`--no-ocr`), because "Click in <window>" is the weakest part of a guide and the engines are local: Windows.Media.Ocr (pywinrt, MIT), macOS Vision (pyobjc, MIT), `tesseract` CLI on Linux when installed (not a Python dependency). Only for click / typing steps without an element name, once per step (`ocr` flag in steps.json, so rebuilds are idempotent), on the raw screenshot. Choosing the text: inside the detected frame shrunk by 4 px (rounded borders stopped tesseract reading "Create"), grayscale + autocontrast, 2x upscale, a 12 px margin in the background colour, then the same inverted (white text on coloured buttons); the line nearest to the click. A button without readable text gets no name — an earlier version looked at neighbours and named the "Create" button "Cancel". Wide, short frames (text fields) take the label above or to the left; placeholders ("e.g. …", "例: …") are never names; leading checkbox glyphs ("[| ]") are stripped; no frame or a tiny one (checkboxes) uses the nearest line within 40 px of the click. tesseract runs with eng+jpn (eng first keeps Latin word spaces; spaces between Japanese words are removed again). On the synthetic demo all seven clicked controls get the same names as the accessibility path, in en and ja. Tests turn OCR off except those marked `ocr`, so titles do not depend on the machine; CI installs tesseract on Linux and uses the built-in engines on Windows and macOS.

- 2026-09-25 — RM-054 `stepcap diff A B`: steps are aligned in order with `difflib.SequenceMatcher` over a key of what the step did (kind + click type + element name after NFKC / case folding; without a name: kind + app + window; keys: the key combination; notes: the first 40 characters). Position on the screen and the step title are not in the key, so moved buttons and edited titles still match. Aligned pairs are "changed" when the screenshots are less than 90 % similar (the thumbnail comparison used for screenshot reuse) or a different value was typed (only when both runs recorded typing); a small change such as one heading stays "same" (98 % similar on the demo). A `replace` block pairs steps by position as "changed" and reports the rest as missing / extra. URLs (host + path) and terminal commands (whitespace-normalised) are compared as sets. Exit code 0 by default like `git diff`; `--fail-on missing|any` for scripts. The HTML report is one self-contained file (JPEG thumbnails as data URIs, blur applied because they come from `work/`). Agent verification = record while the agent works and diff with the reference; it depends on the recorder seeing synthetic input (checked with XTEST on Linux only).
